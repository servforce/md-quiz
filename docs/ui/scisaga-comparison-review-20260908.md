# 两项目 UI 差异分析与改造建议（2026-09-08）

建议以当前 servforce 的业务能力和浅色管理端主题为基础，吸收 Scisaga 的紧凑列表、材料预览与任务入口。优先解决分页、误操作、信息可见性与阅读空间，再处理圆角、阴影和装饰。

本文保留 2026-09-08 对比时的事实与建议。2026-09-09 已按确认范围实施管理端改造，当前状态见 [管理端改造实施与验收](admin-redesign-20260909.md)。**候选人端页面与答题内容本轮不调整**；下文涉及公开验证、资料提交、阅读手势、答题按钮和草稿提示的建议均保留为历史评审，不属于本轮实施范围。新增任务总览，默认首页仍为测验列表。

**首轮具体改造项**

**P1-01：阅读手势与推进、提交分离，两边共有问题。**

事实：整个题目 section 监听触摸；已有有效答案、非请求中，并且左滑或上滑超过 60px 时，触发下一题或末题提交。检查没有区分正文滚动、textarea 内滚动和提交手势。不是每次滚动都会提交：必须满足答案、忙碌状态和位移条件。证据为 [题目模板](../../static/public/views/question.html)、[quiz.js 的触摸与作答动作](../../static/public/modules/quiz.js)。

判断：长题干、多选已选后继续阅读、末题简答回看内容时，这条源码路径有误推进风险；当前没有真机复现，因此不写成每次必现故障。

建议：取消整个阅读区的滑动推进，以明确按钮完成多选/简答的推进和提交。保留既有单选自动推进、计时到期处理、顺序作答和不可回退规则，本项不重定义考试协议。

验收：多选已选、简答非空时，在题干和输入框内任意正常滚动都不发送推进/提交请求；按钮仍按规则提交；请求中不能重复推进；计时到期流程不受影响。测试应覆盖真实作答状态模块与 API 边界。

**P1-02：补齐测验分页，两边共有问题。**

事实：当前与参考的测验接口每页 20 条；页面没有对应翻页入口，`loadQuizzes()` 发送搜索与排序但未传页码。5 条演示数据不会暴露此问题。证据为 [当前测验接口](../../backend/md_quiz/api/admin_quiz_routes.py)、[loadQuizzes](../../static/admin/modules/pages/quizzes.js)、[列表模板](../../static/admin/pages/quizzes.html)。

建议：复用接口已有的 `page / per_page / total / total_pages`，提供总量、当前范围和前后页；搜索、排序切换回第一页。原有后台列表分页规则优先保持一致，不新增一种特殊浏览方式。

验收：使用至少 21 条数据，未知标题时也能浏览到第 21 条；空结果、最后一页、切换搜索/排序、同步后刷新都能保持合理页码；总量取 API，不取当前数组长度。

**P1-03：借鉴 Scisaga 手机答题主操作区。**

事实：[图 12](../../output/project-comparison-20260908/12-mobile-question-comparison.png) 可见参考版整行按钮和独立底部操作区；当前按钮按内容宽度布局，位于普通文档流。两边答案控件都是原生 button，不能说当前无法键盘点击。

建议：手机端设置明确、足够宽的底部主操作区，区分“下一题”“完成本题”“完成并提交”；保留保存时机提示，安全区与内容底部留白一起设计。

验收：390px 窗口、长题、长选项、横屏与软键盘开启时，操作区不遮住最后一项或输入光标；按钮能被触摸和键盘触发；提交状态清晰。常用触控目标以至少 44px 为设计目标；这不是把 44px 宣称为 WCAG AA 的统一最低值。

**P1-04：将邀约卡片改为紧凑业务列表。**

事实：[图 06](../../output/project-comparison-20260908/06-admin-assignments-comparison.png) 同窗口中为 8 条与 4 条完整记录。差异主要来自每条记录都展示 URL、二维码、日期与多个操作，并不等于响应速度或操作效率实测提高一倍。

建议：桌面主行依次为候选人、测验、状态/处理状态、得分、关键时间与主操作；复制入口就近，完整 URL 与二维码在点击后展开；删除等低频危险操作降为次级。手机使用相同字段优先级的纵向摘要，不压缩成横向大表。

保留：状态和处理筛选、疑似 AI 题数、不限时标记、分页、复制链接、处理人、候选人优先与多测验创建等当前实际能力。只整理展示，不合并或改写业务状态。

验收：同一组 8 条基础记录的桌面可见密度明显改善，关键状态无需展开即可判断；二维码与复制不触发行跳转；删除、标记处理的键盘与鼠标行为一致；操作后筛选/分页不意外丢失。

**P1-05：将测验分析提升为宽任务区。**

事实：当前分析面板有固定宽度分桶和横向滚动。图 42 的高分桶位于首屏右侧视野外，不能据此断言不存在高分数据。该能力是当前独有，参考版不能提供完整替代实现。

建议：在测验详情内使用“题目内容 / 测验分析 / 版本历史”任务视图；选中分析时使用工作区主要宽度，先显示日期/版本和分布，再显示答卷记录。短版本历史仍可在内容视图中作为辅助信息。

保留：得分与 Traits 分布、过滤条件、明细联动、版本和时间范围；不恢复为只有题目与历史的参考版。

验收：1600、1280、1024、768、390px 下，普通得分分布的全范围有可理解的概览，高分桶不会因窄侧栏而默认藏在视野外；窄屏如保留横滚须有明确提示；选桶后列表与筛选状态同步。证据为 [详情模板](../../static/admin/pages/quiz-detail.html)、[分析模块](../../static/admin/modules/pages/quiz-analytics.js)。

**P1-06：补关键表单与多选语义，两边共有问题。**

事实：公开多选按钮用颜色 class 表示选中，没有相应选中状态语义；部分 OTP、简答与文件控件缺少明确关联名称。应逐个控件检查，不将所有控件一概说成无 label。

建议：多选用原生 checkbox 或为当前切换按钮补准确的状态语义；验证码、简答、上传控件关联可感知名称和错误信息；发送/提交忙碌状态、错误和成功反馈可被辅助技术获知。

验收：键盘能完成整个流程；辅助技术能区分未选和已选、读出字段及错误；焦点可见且不被固定操作区遮挡。图标按钮仍保留可感知名称。补充真实浏览器/读屏验收后才能判断完整合规情况。

**P1-07：保护当前职位编辑中的未保存修改。**

事实：[职位模块](../../static/admin/modules/pages/job-descriptions.js)已有 `jobDescriptionFormDirty()`，但它目前用于显示“未保存”；`loadJobDescription()` 在取得另一职位后直接覆盖表单，`startCreateJobDescription()` 直接重置。[列表按钮](../../static/admin/pages/job-descriptions.html)直接调用上述加载函数。这是当前独有功能中的源码路径，参考版无对应页面可供移植；本次未录制实际丢稿操作。

判断：编辑长职位描述时，切换一条列表记录或点击新建就可能丢掉未保存内容。因涉及劳动成果保留，本报告将草稿保护列入 P1，视觉打磨和草稿预览列 P2。

建议：复用已有修改检测，在会重置草稿的切换、新建动作前，让用户明确选择继续编辑、保存后切换或放弃修改。保存失败应保留草稿和当前选中项，不自动跳走。Git 来源职位继续只读。

验收：标题、正文、状态、关联测验修改都被正确识别；继续编辑不丢输入，明确放弃才重置，保存失败不切换。已保存或未修改时正常切换，不无故增加确认步骤。

**第二轮值得适配的内容**

1. **测验和候选人列表（P2）**：参考列对齐与稳定行高。测验主行保留题数、答题人数、时长、版本、公开状态和排序；长 ID 与标签降低权重。候选人主行保留最多两条现有摘要，分别提供答卷链接，姓名进入档案；避免在当前外层 button 内嵌套链接。当前 API 已有摘要 token，无需先新增答卷查询字段。两边测验图都完整显示 5 套、候选人图都完整显示 8 人，不能将邀约页的密度差异推广成所有列表翻倍。
2. **档案与答卷详情（P2）**：把阅读、判断和编辑组织为清楚分区。保留职位关系、简历评价分数与正文编辑、收藏和管理员评价；“新增面试记录”与“修订简历评价”分别说明追加和覆盖语义。教育概览只保留摘要，避免同一教育全文重复。长评价提供宽阅读/编辑区；短结论与编辑器可以保留有明确边界的内部滚动。Traits 选项权重保留为可查看详情，默认突出维度与结论。
3. **材料预览（P2）**：参考就地查看图片与档案核对的路径。预览图片，PDF/其他文件保留准确的类型说明和下载；当前没有通用 PDF 阅读器，参考版也不是。沿用当前鉴权和 UTF-8 文件名处理，新增受认证的图片预览分支，无需新增名片存储列。参考放大层已有 Escape 和 dialog 语义，但缺少完整焦点限制与恢复，移植时应补齐。
4. **任务型总览（P2）**：参考待处理入口和最近答题，不复制所有大数字卡。推荐呈现待处理结果、近期完成、失败任务及直接入口。汇总取真实全量/筛选聚合；说明时间范围。是否替换默认首页在它能承载主要日常任务后决定，不为增加页面而改默认跳转。
5. **日志（P2）**：使用时间、分类、事件、操作者/日志编号的对齐视图，保留当前起止时间和用时。事件可展开查看上下文；如新增全局搜索/类型筛选，应让后台查询和总量口径一并支持，不能只筛当前页。
6. **状态与配置（P2）**：在桌面为六列表格分配足够宽度，配置可移到较低频的任务视图。当前 `.admin-data-table__scroller` 本身支持横滚，因此要改进空间和发现性，不应通过 `overflow:hidden` 掩盖溢出。相同缺失配置避免在提醒、用量卡和接入卡重复大段展示，保留一个明确原因与处理入口。
7. **MCP（P2）**：能力范围和接入说明保留；客户端配置按选择展示并提供复制，减少长页扫描。OpenClaw 与 Hermes 是示例客户端差异，不足以证明某版协议能力更多。界面可统一“已启用/未启用”；配置路径、协议和鉴权等对接用户需要的技术说明继续保留。
8. **仓库同步摘要（P2）**：用“未同步 / 排队 / 同步中 / 成功 / 失败”和经实际字段确认的结果计数替代默认 `pretty(syncState)` JSON。未提供的数量不伪装成零，错误说明可直接读懂，调试详情折叠且仅展示核准字段。保留重新绑定的清理范围、确认和任务忙碌限制。
9. **公开邀约筛选（P2）**：参考 Scisaga，在测验搜索、排序旁增加“全部 / 已开放公开邀约”。当前 API 尚无此条件，应在后台分页前筛选，并返回正确总量；不能只过滤已下载的 20 条。
10. **对象面包屑与列表上下文（P2）**：在已有面包屑上补当前测验/候选人/答卷名称，异步加载时确认对象属于当前路由。返回列表保留筛选、排序、页码和滚动位置；浏览器前进、后退和刷新使用一致约定，不显示上一对象名称。
11. **公开验证和资料提交（P2）**：把测验名称、当前步骤、必要说明与表单靠近，手机减少重复介绍。公开验证先聚焦未完成身份字段，定向验证优先验证码；手机号补合适输入类型和自动填充。保留已有 OTP 方向键、退格和粘贴处理。已有简历明确“继续使用 / 替换”，失败说明真实原因。管理端建档和上传已有必选职位约束，应将职位选择放在上传前并解释禁用原因，保留异步解析进度。
12. **验证受限状态（P2，两边共有）**：服务端已返回 `locked`，前端却仍展示普通验证码输入。依据该标志显示“当前链接验证已受限，请联系邀请方处理”，停用无效输入和发送；与可恢复的短信冷却分开。服务端仍拦截受限记录，本项是状态表达缺口，不是已证实的验证绕过。
13. **未提交草稿提示（P2，两边共有）**：题下说明多选/简答完成后才保存，但返回提示统一说“当前进度会保留”。有未提交修改时应明确“已完成题目的进度已保留，本题内容尚未提交”；不在文案调整时擅自新增自动保存或提交动作。
14. **职位草稿预览（P2）**：当前预览读取已加载的 `content_html`，编辑后的正文尚未保存时会继续展示旧内容。预览应使用当前草稿并标明未保存，复用现有服务端 Markdown 渲染与清洗，新增不持久化的预览请求；不能通过自动保存来冒充预览。
15. **手机导航与页内标签（P2）**：保留当前原生链接、文字和 `aria-current`，不复制参考版强制等分的小按钮。现有页内 tab 补关联面板、方向键及焦点管理；检查活动导航项可见、吸顶条不相互遮挡。
16. **登录与一般文案（P2/P3）**：当前登录任务清楚，可减少六项功能宣传所占比重。“招聘搭子”需与项目多场景愿景一致；参考版的泛化引导语也不直接复制。删除“恢复每日统计表”“当前规划”等实现过程用语，直接描述用户当前能做什么。

**布局调整时必须保持的数据含义**

- 测验列表的 `respondent_count` 是已进入测验的去重答题人数，不能换成“答卷份数”而沿用相同值。
- 测验分析的日期范围按已完成记录的完成时间、进行中/判卷中记录的进入时间筛选，不等于该期间发出邀约的总量。概览、分布和明细要使用一致范围。
- 候选人的简历匹配度目前是简历评价中的一个指标，不是每个关联职位各有独立评分；多职位标签不能暗示已分别计算。
- 简答题“疑似 AI”是管理员人工标记能力，不能在重新设计时包装为自动检测结论。

这些边界已核对列表接口、分析查询、候选人 schema 与评价更新路径，详见文末分项审查。

**明确不照搬的内容及证据**

- **登录页静态健康状态**：Scisaga [登录模板](https://github.com/Scisaga/md-quiz/blob/3b2a3eb110480ccd1ee88808479a9bd7deffc050/static/admin/pages/login.html#L18) 写死“系统正常”。当前 [中文状态映射](../../static/admin/modules/shell.js) 和 [按状态着色](../../static/assets/css/admin/shell.css) 更可信，应保留；没有状态时显示未知。
- **总览统计口径**：Scisaga [dashboard.js](https://github.com/Scisaga/md-quiz/blob/3b2a3eb110480ccd1ee88808479a9bd7deffc050/static/admin/modules/pages/dashboard.js#L69) 的完成数来自返回页 `items`，分母使用 `total`；[邀约接口](https://github.com/Scisaga/md-quiz/blob/3b2a3eb110480ccd1ee88808479a9bd7deffc050/backend/md_quiz/api/admin_assignment_routes.py#L46) 每页 20 条。超过一页时不能将其作为全量完成率。测验数组长度也不能替代分页接口总量。
- **把日志编号叫 Trace**：参考模板使用 `trace_id || id`。当前 [日志序列化](../../backend/md_quiz/api/admin.py) 返回 `id`、`actor` 等，没有该顶层 `trace_id` 字段；当前 [system_log 表与查询](../../backend/md_quiz/storage/db.py) 有日志 ID。先准确展示日志编号，需要端到端追踪时再核对真实关联字段和链路。
- **将现有业务缩减为参考版**：不能丢失职位、关联测验/候选人、简历评价编辑、分析过滤、多个作答摘要、疑似 AI 标记、处理筛选以及稳健文件下载。参考版没有同页，不意味着当前功能多余。
- **装饰层整包迁移**：两边都有浅色后台和蓝绿品牌，不需要重新换字体、品牌或整体主题。优先保留当前实心表面；更大渐变、模糊和阴影没有经过性能与可读性实测支持，不列为必要升级。
- **名片当作纯 UI 补丁**：名片需存储字段、文件接口、公开资料模式、复用/替换状态和管理档案协同。已核对的参考实现收集名片原图，不代表自带名片 OCR。只有实际业务需要时再做完整功能；不能只展示没有后端支持的“上传名片”按钮。

| 批次 | 工作 | 边界 | 完成条件 |
| --- | --- | --- | --- |

通用验收：390、768、1024、1280、1600px 与放大场景；长姓名/标题、多个测验、空结果、加载失败、只剩最后一页；键盘和触摸；固定栏不遮挡；所有资源本地加载。数据表的必要二维滚动应局限在明确容器内，不把整页推宽。

前端实施遵守 [Utility 规则](utility-authoring.md)：布局与断点写入页面模板，共享 CSS 只承载真正共享的皮肤和机制。不通过新增全局 override 修一张图，不直接复制 `admin-r-*` 整套模板。已有结构测试应随最终用户行为与布局契约更新，保留真实模块边界验证。

**验收标准参考**

- [W3C Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：WCAG 2.2 AA 的指针目标基准为 24×24 CSS px，并有间距等例外；本报告 44px 为更宽裕的常用触控设计目标。
- [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow)：必要的二维数据表可以有独立滚动区；其他内容仍应随窗口重排。
- [W3C 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：材料预览若采用模态形式，应处理焦点进入、限制、Escape 关闭和关闭后返回。
